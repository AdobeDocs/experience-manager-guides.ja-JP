# 2026.08.0 リリース（2026年8月）の新機能

この記事では、Adobe Experience Manager Guides as a Cloud Serviceの2026.08.0 リリースで導入された新機能と強化機能について説明します。

このリリースで修正された問題のリストについては、[2026.08.0 リリース &#x200B;](fixed-issues-2026-08-0.md)で修正された問題を参照してください。

2026.08.0 リリース [&#128279;](../release-info/upgrade-instructions-2026-08-0.md)の アップグレード手順について説明します。


## マップを管理し、出力を公開するための新しいマップコレクション

新しいマップコレクションは、マップコレクション管理と出力生成アクティビティを単一のインターフェイスにまとめます。 マップやプリセットの管理、出力の生成と公開、生成と公開履歴の表示などを1か所で行うことができます。 関連する公開タスクをまとめることで、マップコレクションを使用して、複数のマップと関連する言語をまたいで出力アクティビティを追跡することが簡単になります。 このアップデートでは、大規模なマップコレクションで発生するパフォーマンスの問題にも対処します。

![](assets/new-maps-collection.png)

詳細については、[出力生成に新しいマップコレクションを使用](../user-guide/generate-output-use-new-map-collection-output-generation.md)を参照してください。


## Git コネクタを使用してGit リポジトリからコンテンツを取得する

Experience Manager GuidesにGit Connectorが導入されました。これにより、Git リポジトリからExperience Manager Guidesにコンテンツを読み込むことができます。 コンテンツをインポートした後も、引き続きExperience Manager Guidesを使用して、オーサリング、レビュー、翻訳、公開のワークフローを進めることができます。

インポートしたコンテンツを最新の状態に保つために、Git Connectorでは、ソースリポジトリからコンテンツを再取得して更新を取り込むこともサポートしています。 また、コンテンツの更新を識別するインテリジェントな変更検出機能、インポートおよびリフェッチ操作中にトピックおよびマップのGUIDを保持する機能、Experience Manager Guidesで既に利用可能なリポジトリコンテンツとコンテンツの違いを管理する競合解決機能を備えています。 詳しくは、[Git コネクタを使用したコンテンツの読み込み](../user-guide/web-editor-git-connector.md)を参照してください。

![](assets/git-bulk-importer-import-all.png)


## Experience Manager Guides、AI アシスタント統合にMCP サポートを追加

Experience Manager Guidesでは、MCP （Model Context Protocol）の統合がサポートされるようになりました。これにより、Anthropic ClaudeなどのAI アシスタントがAEM Guides環境に直接接続できるようになります。

認証済みの利用者は、既存のAEMの権限の下で作業しながら、単一のMCP エンドポイントを通じて、トピックやマップの管理、ベースラインの作成と書き出し、自然言語を使用してレポートを生成することができます。 これにより、ナビゲーションを多用する反復的なタスクが排除され、ドキュメントチームはチャットアプリケーションや、CursorやVisual Studio CodeなどのMCP対応の開発者ツールをまたいで、より効率的に作業できるようになります。 詳しくは、[Adobe Experience Manager Guides MCP Serverの使用](../install-conf-guide/conf-aem-guides-mcp.md)を参照してください。


## 機能強化を見る

### レビュータスクを別のレビューアーに委任

レビューアーは、レビュータスクで利用可能な新しい&#x200B;**委任** オプションを使用して、レビューが作成者に戻る前に、別のユーザーがレビューに参加することを推奨できるようになりました。 これは、コンテンツの一部がレビュー担当者の専門知識を超えている場合や、レビューを完了する前に別の意見が必要な場合に、プロジェクト管理者を通じてリクエストを転送する必要がない場合に役立ちます。

「委任」オプションを選択すると、推奨事項が作成者に送信され、作成者は推奨事項のレビュー担当者をタスクに追加するかどうかを決定します。 [&#x200B; レビュータスクを別のレビューアーに委任](../user-guide/review-complete-review-tasks.md#delegate-a-review-task-to-another-reviewer)の詳細をご覧ください。

![](assets/review-delegate-option.png){width="350"}

### レビューUIにタスクの説明が表示されるようになりました

レビューアーは、通知メールのみに依存するのではなく、レビューエクスペリエンス内でタスクの説明を直接表示できるようになりました。 レビュータスクの作成中に入力された説明は、レビューの詳細ダイアログに表示され、レビューUIとエディターインターフェイスの両方で&#x200B;**情報** アイコンからアクセスできるようになります。

これにより、レビュー担当者は、レビュー全体を通じて手順、範囲、焦点を当てた領域にアクセスできます。 詳細については、[&#x200B; レビュー用にトピックを送信](../user-guide/review-send-topics-for-review.md)を参照してください。

![](assets/review-details.png){width="350"}


### レビュー時のタグ付けリストでのユーザーID

レビューのコメントまたは返信でユーザーをタグ付けすると、タグ付けドロップダウンに各ユーザーのメールアドレスがユーザーIDと共に表示されるようになりました。 これにより、正確なレビュアーを特定して選択することが容易になります。特に、表示名が不明瞭な大規模組織では特に重要です。

メールアドレスが利用できない場合は、代わりにユーザーIDが表示されます。 レビューUIの操作について詳しくは、コメント内の[&#x200B; タスクユーザーのタグ付け](../user-guide/review-topics.md#tag-task-users-in-a-comment)を参照してください。


### トピックのすべてのレビュータスクを表示

作成者は、現在開いているトピックに関連付けられたすべてのレビュータスクを、開いているか閉じているかをコメントパネルから直接表示できるようになりました。 ドロップダウンには、トピックが属するすべてのレビュータスクと、各タスクの状態およびプロジェクトが一覧表示されます。トピックを離れたりレビュープロジェクトを切り替えたりすることなく、コメントを表示できます。 [&#x200B; トピックのすべてのレビュータスクを表示](../user-guide/review-address-review-comments.md#view-all-review-tasks-for-a-topic)の詳細を確認します。

![](assets/review-task-selection-dropdpwn.png){width="350"}

### DITAVAL条件によるレビュー体験の向上

レビュータスクに1つ以上の添付されたDITAVAL ファイルが含まれている場合、条件パネルには、各条件が、添付されたDITAVAL ファイルと一致するように事前設定された切り替えスイッチとして表示されるようになりました。これにより、レビュー担当者は、レビュー開始者が意図した方法でコンテンツを確認できます。 トグルをオフにすると、そのコンテンツはレビューから非表示になり、オンにすると元に戻ります。

詳細については、DITAVAL ベースの条件[&#128279;](../user-guide/review-topics.md#conditions-panel-with-ditaval-based-conditions)を含む条件パネルを参照してください。

![](assets/review-condition-panel-ditaval.png){width="350"}

## 公開の機能強化

### 出力プリセットをテンプレートとして使用

管理者は、出力プリセットをテンプレートとして指定できるようになり、マップコンソールを通じて、1つのアクションでフォルダープロファイル内のすべてのマップに標準化された設定を適用できるようになりました。 テンプレートが適用されると、影響を受けるマップの数が表示され、ロールアウト前に管理者に完全な可視性が提供されます。 一貫性を保つために、テンプレートプリセットは管理者のみが変更でき、テンプレートプリセットの出力生成は無効になります（プリセットをテンプレートとして設定する前に出力が既に生成されている場合を除く）。

詳しくは、[出力生成のテンプレートプリセットの設定](../install-conf-guide/template-presets-output-generation.md)を参照してください。

### コンテンツの健全性チェックによるコンテンツ品質の検証

コンテンツのヘルスチェックは、公開前にDITA マップ全体でコンテンツの品質を検証するのに役立ちます。 管理者は、壊れたリンク、重複ID、Schematron検証のチェックを組み合わせることで、再利用可能なヘルスチェックプリセットを作成できます。

作成者は、DITA マップまたは選択したベースラインでヘルスチェックを実行して、関連するトピックとマップ間の問題の統合レポートを生成できます。 詳しくは、[&#x200B; マップ上でヘルスチェックを実行](../user-guide/map-editor-other-features.md#run-health-check-on-a-map)を参照してください。


## 翻訳の機能強化

### 翻訳プロジェクトのカスタムフォルダーパスの指定

翻訳用のコンテンツを送信する際に、デフォルトで`/content/projects`の下にある単一の場所にあるすべてのプロジェクトではなく、新しい翻訳プロジェクトが作成されるフォルダーを選択できるようになりました。 これにより、乱雑なプロジェクト構造を回避し、翻訳プロジェクトが増えるにつれてページの読み込みのパフォーマンスを向上させることができます。

詳しくは、[翻訳プロジェクトの作成](../user-guide/translate-documents-web-editor.md#create-a-translation-project)を参照してください。

## 学習コンテンツの機能強化

このリリースの製品トレーニングおよび学習コンテンツ機能では、次の機能強化を利用できます。

- 新しい&#x200B;**学習者エクスペリエンス** タブがSCORM出力設定で利用できるようになりました。これにより、学習者がSCORM出力を操作および操作する方法を設定できます。 設定は、一般、ナビゲーション、クイズの下に整理され、コンテンツのアクセシビリティ、ナビゲーションフロー、クイズ行動を制御して、カスタマイズされた学習体験を実現します。

  **ナビゲーション**&#x200B;では、ページで&#x200B;**次** ボタンを有効にするか無効にするかを制御できるようになりました。これにより、すべてのインタラクティブ要素を開く、すべてのメディアを視聴するなど、ページで指定された条件を満たした後にのみ学習者が進むことができます。 詳しくは、[SCORM プリセットの設定](../learning-content/config-scorm-preset.md)を参照してください。

  ![](assets/learner-experience.png){width="650"}

- SCORM出力で学習者のPDF ダウンロードを有効にできるようになりました。 このオプションを有効にすると、PDFのダウンロードアイコンが公開されたSCORM出力に追加され、学習者はPDF版のコースコンテンツをダウンロードしてオフライン参照できるようになります。 これにより、学習者がコース教材にアクセスする方法の柔軟性が高まり、作成者が公開されたエクスペリエンスをより詳細に制御できるようになります。 設定の詳細と前提条件については、[学習者がコース PDFをダウンロードすることを許可する](../learning-content/config-scorm-preset.md)を参照してください。

  ![](assets/pdf-icon.png){width="650"}

- コースの公開出力で、学習者は、送信された回答を再検討するクイズの試みを完了した後、**回答を確認** オプションを使用して、どの回答が正しいか正しくないかを確認できるようになりました。 クイズ [&#128279;](../learning-content/quiz-insert-questions.md#question-properties)の質問プロパティについて詳しく説明します。

  ![](assets/review-answer-quiz.png){width="650"}

- コース内のナレッジチェックの質問で、学習者が誤った回答を選択すると、**再試行** ボタンが表示され、質問を再試行できるようになりました。 この動作は、シングルセレクトとマルチセレクトのナレッジチェックで一貫しています。 詳細については、挿入メニュー[&#128279;](../learning-content/lc-other-insert-options.md)のその他のオプションを参照してください。

- HTML トピックがLearning Group マップに追加されると、`format="html"`属性が対応する`topicref`に自動的に追加されるようになり、DITA-OT 4.xで正しい処理と公開が保証されるようになりました。 詳細については、[&#x200B; コースに既存のコンテンツを追加する](../learning-content/manage-course.md#add-existing-content)を参照してください。
